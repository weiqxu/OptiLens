# 0.1 首版实现记录

日期：2026-10-20

## 交付范围

首版是一个只监听本机的 Web 服务。实现了 Calcite 真实优化、完整阶段快照、局部规则事件及可交互计划对比，并支持历史运行和导入导出。

## 技术决策

- Java 17、Calcite 1.39.0、Maven；统一 Jackson 2.18.3 依赖版本。
- JDK HTTP Server 提供同源 API 和静态页面。
- 原生 JavaScript 模块与 SVG 实现图形界面，首版无需前端打包工具。
- JSON 原子文件替换保存记录；读取时校验成功结果。
- 每个任务使用独立 JVM，避免优化超时或失败占住 HTTP 服务。
- 6 个案例、5 个规则组；所有图形结果来自实时执行或用户导入，页面不预填模拟计划。

原计划中的 TypeScript / React 为建议选型。首版采用较轻量的实现，后续可在保留 API 和记录格式的前提下迁移。

## 采集结果与边界

1. SQL 先经过解析、校验和 SQL-to-Rel 转换。初始快照从转换后开始，不声称捕获此前的每条改写。
2. 每个所选规则组运行独立 HepPlanner，阶段边界保存完整计划。
3. 规则尝试只处理 `isBefore()` 回调。表达式产生也只处理注册前回调，此时可同时保存旧匹配和新表达式。
4. 事件快照明确标为局部表达式；不使用局部事件猜测整条查询的中间状态。
5. HepRelVertex 在快照时展开为当时表达式，节点、属性和输入关系立即转换成独立数据。
6. 常量化简需要为关系表达式所属 cluster 的 planner 设置执行器；不能只配置实验中的 HepPlanner。
7. 未采集完整等价集合、拒绝原因和最终候选归因，不展示这些信息为已确认事实。

## 验证范围

- JUnit：真实 Calcite 规则、常量求值、NULL/外连接边界、记录往返和非法结构。
- HTTP 与进程：任务执行、导出后导入、跨来源请求拒绝、服务重启恢复和超时失败。
- Node.js：差异匹配、歧义保留、共享子图布局。
- 浏览器：查询运行、阶段/事件切换、节点详情、缩放、导入导出、错误反馈、无规则程序、键盘操作和窄屏布局。

以上测试不构成对所有 SQL 的语义等价证明。首版未提供数据执行环境，跨引擎结果等价和性能基准不在本次验证范围内。

## 数据库选择与规则目录扩展

- 数据库类型当前限定为 Calcite；请求显式携带 `database: calcite`，旧请求缺省兼容。
- 自动读取 Calcite 1.39.0 内置规则目录并列出 JDBC 规则类型，共 222 个条目，另保留 5 个常用规则组。目录范围在页面及 README 中注明。
- 支持名称搜索、分类筛选、源码链接、单条逻辑规则执行、恢复常用组合及清空选择；需要其他环境的规则展示原因并禁止选择。
- 每次最多 32 个规则阶段；导入记录校验同步调整，原有规则组和格式版本 1 保持兼容。
- 新增规则目录完整性、单规则真实变换、扩展程序往返、未知数据库和不可用规则拒绝测试；浏览器回归用例覆盖新选择流程。
