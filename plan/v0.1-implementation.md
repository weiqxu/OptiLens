## Delivered scope

The first release is a web service that listens only on the local machine. It provides real Calcite optimization, complete stage snapshots, local rule events, interactive plan comparisons, run history, and import and export.

## Technical decisions

- Java 17, Calcite 1.39.0, and Maven, with Jackson dependencies aligned to version 2.18.3.
- JDK HTTP Server for the same-origin API and static pages.
- Native JavaScript modules and SVG for the interface, without a frontend bundler in the first release.
- JSON persistence using atomic file replacement, with validation of successful results on read.
- A separate JVM for each job so that optimization timeouts or failures do not tie up the HTTP service.
- Six examples and five common rule groups. All visual results come from actual runs or user imports; the page contains no prefilled simulated plans.

TypeScript and React were suggestions in the original plan. The first release uses a simpler implementation, which can later be migrated while preserving the API and record format.

## Collection behavior and boundaries

1. SQL is parsed, validated, and converted to relational expressions. The initial snapshot starts after conversion and does not claim to capture every preceding rewrite.
2. Each selected rule group runs in a separate HepPlanner, with complete plans captured at stage boundaries.
3. Rule attempts process only the `isBefore()` callback. Expression production also processes only the callback before registration, when both the original match and the new expression can be captured.
4. Event snapshots are explicitly labeled as local expressions. Local events are not used to guess the intermediate state of the complete query.
5. HepRelVertex nodes are unwrapped to their current expressions during snapshot creation. Nodes, attributes, and input relationships are immediately copied into independent data.
6. Constant reduction requires an executor on the planner belonging to the relational expression's cluster; configuring only the experimental HepPlanner is insufficient.
7. Complete equivalence sets, rejection reasons, and final candidate attribution are not collected and are not presented as confirmed facts.

## Validation scope

- JUnit: real Calcite rules, constant evaluation, NULL and outer-join boundaries, record round trips, and invalid structures.
- HTTP and processes: job execution, export followed by import, cross-origin request rejection, restart recovery, and timeout failures.
- Node.js: difference matching, preservation of ambiguity, and shared-subgraph layout.
- Browser: query runs, stage/event selection, node details, zoom, import/export, error feedback, programs without rules, keyboard interaction, and narrow-screen layout.

These tests do not prove semantic equivalence for all SQL. The first release provides no data execution environment; cross-engine result equivalence and performance benchmarks are outside this validation scope.

## Database selection and rule catalog extension

- Database selection is currently limited to Calcite. Requests explicitly carry `database: calcite`; older requests that omit the field remain compatible.
- The catalog reads Calcite 1.39.0 built-in rules and lists JDBC rule types: 222 entries, plus five common rule groups. The interface and README state the catalog's scope.
- Name search, category filters, source links, individual logical rule execution, restoration of common groups, and clearing the selection are supported. Rules requiring other environments are disabled with an explanation.
- Each run accepts up to 32 rule stages. Import validation has been updated accordingly; original rule groups and record format version 1 remain compatible.
- Added tests cover catalog completeness, real transformations from individual rules, round trips for expanded programs, and rejection of unknown databases and unavailable rules. Browser regression tests cover the new selection workflow.

## Rule explorer page (2026-10-22)

- Added `/rules` with a database selector, a searchable list of 222 individual catalog entries, category/example filters, and a selected-rule detail panel.
- Added 26 verified SQL examples covering expression reduction, predicate/projection rules, joins, aggregates, set operations, literal values, and empty-result pruning. Every example executes exactly one named rule and produces real transformation evidence in Calcite 1.39.0.
- The detail panel runs examples through the existing isolated job service and supports full-stage/local-event views, graph inspection, raw plans, downloads, retries, and opening the selected rule in Query lab. Pending and completed runs are reused within the page session; stale responses cannot replace the selected rule.
- Rules without an example or required environment are labeled explicitly. Date-range rules are marked unavailable until connection/time-zone configuration is integrated.
- API, example execution, browser navigation, rapid selection, failure/retry, keyboard, and narrow-screen checks cover the new workflow.
